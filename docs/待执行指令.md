# 待执行指令

> **性质声明**：本文件是「**待执行指令**」，不是历史记录。
> 因此它**必须与仓库实测保持一致**——已完成的项**立即删除或标记完成**，不得作为历史存档留在原地。
> （与台账的「历史快照不改写」正好相反：**判据是「已发生」还是「待做」**。）

## 为什么单列

交付链里有一批事 **AI 做不了**：平台面板配置、密钥轮换、分支保护、仓库元数据。
它们**不是代码缺口**，因此**不进 `docs/GAP台账.md`**——那里记的是框架自身「该做而未做」的事。
若不单列，它们**不在任何台账里、也没人认领**，最后表现为「功能做完但联调不通」。

## 每行只答三件事

**缺什么 / 在哪补 / 谁做**。「谁做」只有两种取值：**人** 或 **平台**——**没有一条 AI 能代办**。

| **缺什么** | 演示账号的密码**已被公开发布过**，必须轮换 |

- 仓库无任何凭据泄漏（已逐行扫描 `README.md` / `README.en.md`，仅占位符与已注明的本地默认值）

**判据**：轮换后，用旧密码登录必须失败。

## 2. 开启 `main` 分支保护并设置 required check

| 项 | 内容 |
| :--- | :--- |
| **缺什么** | `main` **没有任何分支保护**，两个 CI 作业都**不是 required check** |
| **在哪补** | GitHub → Settings → Branches → Add branch protection rule |
| **谁做** | **平台**（仓库管理员在 GitHub 上配置） |
| **阻塞** | 否——但**「前端用例在 CI 矩阵内」这句话目前是空的** |

**实测依据**：

```
gh api repos/Yotoha0303/go-order-management-system/branches/main/protection
→ {"message":"Branch not protected","status":404}
```

这不是「无法判定」：同一端点对不存在的分支返回**不同文案**（`"Branch not found"`），且 token 的 `permissions` 含 `"admin": true`。
**403 才是无法判定；404 + `Branch not protected` 是明确回答。**

**后果**：一个 CI 失败的 PR **仍可合并**。前端作业存在、能跑、能红，但**没有任何机制强制它**。

**需要设为 required 的两个作业**：
- `Test, Vet, Validate, Build`
- `Frontend (tsc, eslint, vitest browser, build)`

**判据**：保护开启后该端点返回 200 + 规则 JSON，且 `required_status_checks.contexts` 含上述两个作业名。

关联：`GAP-017` DoD ②（Issue #16）。

| **谁做** | **人**——但**不是技术限制**：`gh` 具备该能力，AI 可执行；列在此处是因为它**改的是公开可见的仓库元数据**，属对外动作，**须经用户明示授权**后才做 |

## 4. 在真实云端环境验证 Redis TLS 握手

| 项 | 内容 |
| :--- | :--- |
| **缺什么** | 真实云托管 Redis（`rediss://`）的 TLS 握手**从未实测** |
| **在哪补** | 部署环境：配置 `REDIS_URL` / `REDIS_USERNAME` / `REDIS_PASSWORD` / `REDIS_TLS` 后启动，观察启动日志 |
| **谁做** | **人**（需要云端 Redis 凭据） |
| **阻塞** | 否——但**「云端 Redis 已生效」这句话目前没有端到端证据** |

**当前证据强度**：仅本机 loopback 的真实 TLS RESP 服务（覆盖拒绝 / 成功 / 明文对照 / 认证失败四向）。
**不是**云托管服务的真实握手——证书链、SNI、代理行为都可能不同。

**判据**：启动日志出现 `redis connected`（而非 `redis connection failed; … degraded to pass-through bypass`），且下单接口在压测下优先触发 Redis Lua 预扣。

关联：`GAP-014`（Issue #14，已 `CLOSED`——本项是其**残余验证**，不改变该结论）。
