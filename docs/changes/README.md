# docs/changes/ — 变更记录留痕（足迹锚）

> **足迹锚（AGENTS.md §0.2）**：回答**「这一步具体改了什么、为什么、怎么验证的」**。
> 遵循 02 开发门禁：**先写后填**。

---

## 规范要求

1. 每次提交或任务迭代，必须在 `docs/changes/` 下新增一个按三位数字递增的 Markdown 记录文件，如：
   - `001-fix-gap-001-redis-pre-deduct-timing.md`
   - `002-fix-gap-002-idempotency-rr-conflict.md`
2. **先写后填**：在动手修改代码前，先创建该文档并写明：
   - 本次变更的目标与关联的 GAP / Issue 编号
   - 拟修改的文件列表
   - 预期的正向实测命令与负向证伪命令
3. **完成自验后回填**：
   - 贴入终端真实的 stdout 与 exit code（D1 纪律：读到才算）
   - 验证无误后，随同代码一起原子提交。
