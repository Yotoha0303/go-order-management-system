## 一、项目名称

**Go 订单库存一致性服务：高并发扣减、幂等下单与最终一致性**

技术栈：Go 1.25 · Gin · GORM · MySQL 8.4 · Redis 7.2 · RabbitMQ 4.1 · React 19 · TypeScript · Docker Compose · GitHub Actions

项目链接：`https://github.com/Yotoha0303/go-order-management-system`

---

## 二、一句话定位

一个把**订单库存主链路的并发正确性**做扎实的后端服务：下单幂等、防超卖、跨表事务一致、订单状态机、超时取消与库存回补、用户数据隔离。

**不是** CRUD 堆量，也**不是**完整电商平台——外围（购物车 / 支付 / 物流 / 优惠券）刻意不做。

---

## 三、后端岗位版（4 条）

- 设计下单事务，把幂等记录、订单主表、订单明细、库存扣减、库存流水、超时 Outbox 纳入**同一 MySQL 事务**，异常整体回滚；库存采用**行锁 + `stock_quantity >= quantity` 条件更新**防超卖，并按 `product_id` 升序加锁消除多商品循环等待。
- 基于**用户级复合唯一索引 + SHA-256 请求摘要**实现创建订单幂等：相同请求返回原订单，不同请求复用 Key 返回冲突；把 Redis 预扣提到事务**之前**，售罄时零 DB 访问。
- 用**事务 Outbox + RabbitMQ 分级 TTL 阶梯队列 + DLX + Publisher Confirm + 手动 ACK** 实现待支付订单超时取消；以队列级 `x-message-ttl` 消除单消息 TTL 的**队头阻塞**，消费者用状态条件更新保证重复消息不重复回补库存。
- 用 **pprof 剖析 + 压测**定位读链路瓶颈：100,000 请求 / 50 并发下 **P95 19ms、P99 23ms、0 失败**；剖析发现访问日志中间件占 **22.2% CPU**，并区分出平台级 `cgocall` 开销（39.3%）与真实业务开销。

## 四、平台 / DevOps 版（4 条）

- 建立 **CI 零跳过断言**：集成测试开关打开时任何 `t.Skip` 都让流水线变红——防止「本机全绿、CI 全红」的静默失真（该失真真实发生过：测试库名含连字符导致 CI 连续 15 次失败而无人察觉）。
- 用 **BuildKit 缓存持久化**（`docker/build-push-action` + `type=gha,mode=max`）把 Docker 构建从 **235s 压到 5s**，Go 作业整体 **366s → 127s**；两作业并行，流水线墙钟 **3m52s**。
- 为 **pprof 剖析端点**设计安全边界：默认关闭、独立端口、**只绑回环**、非法布尔值**启动即失败**（不静默当 false）；远程实例通过 SSH 隧道剖析，云端不开口子。
- 以 **D3 判据可证伪**为准则：每条新判据都配负向用例并**逐条做变异注入验证**（掏空校验 / 短路回环检查 / 静默吞异常 ⇒ 测试必须变红）。

## 五、全栈岗位版（3 条）

- 用 Go/Gin/GORM + React/TypeScript 构建订单库存系统，覆盖 JWT 认证、最小 RBAC、商品库存管理、幂等下单、状态流转、超时取消与操作审计。
- 前端以**稳定 `rowId`**（非数组 index）作列表 key，修复删除中间行导致的 Select 状态残留；提交失败清空幂等 Key，避免重试被幂等键拦成「处理中」。
- 解决 **63 位 Snowflake 主键经 `JSON.parse` 精度截断**导致详情/支付/完成/取消四条链路全 404 的问题——序列化侧统一字符串化，并补**原始字节断言 + 浮点往返失真的负向用例**。

## 七、表述纪律（写简历时自查）

1. **每个数字必须能指出采集命令与制品路径**。本文件每条都给了。
2. **不得把「同机压测」写成「生产吞吐」**。本机客户端与服务共享 16 核，客户端自身也吃 CPU。
3. **不得把两个口径不同的数字相比**。2026-07-11 那份（Docker 部署 / 1000 商品 / 1400 RPS）与本次（原生进程 / 125 商品 / 3073 RPS）**不可直接比**——部署形态、客户端位置、数据量三项都不同。
4. **不得写「支撑 N 万 QPS」这类无制品支撑的话**。
5. **写「发现了什么」比写「用了什么」更有说服力**——例如「pprof 定位到访问日志占 22.2% CPU」比「使用了 pprof」有价值。
